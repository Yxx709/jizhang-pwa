# 小账本（个人版原型）

一个本机优先的 iPhone 主屏幕网页记账本。没有账号、后台、统计服务或第三方分析代码。账单写入浏览器 IndexedDB；备份由用户手动导出 JSON。

## 当前范围

- 今日与本月支出汇总
- 手动支出、收入和退款记录
- 退款可关联到原支出；只有已关联的退款会冲减净支出
- 从快捷指令通知内容生成待确认草稿
- 本地 JSON 备份与恢复
- PWA 主屏幕入口与离线缓存

通知草稿链接格式：

```text
https://你的HTTPS页面地址/#capture?source=wechat&title=微信支付&text=咖啡店%0A支付成功%20¥28.00
```

`source` 可用 `wechat`、`alipay`、`shopping` 或 `other`。通知原文仅作为 URL 片段传入（片段不会随网页请求发给静态主机）；页面读取后会立即清除地址栏片段。但 Safari 本地历史、屏幕截图或快捷指令日志仍可能短暂保留输入内容，因此不要把它当作密码或账户凭证。

## 本地预览

需要 Node.js 18 或更新版本：

```powershell
node server.mjs
```

打开 `http://127.0.0.1:4173`。本地预览可检验页面和样例通知；不能直接让 iPhone 访问本机回环地址，也不满足 iPhone 安装 PWA 所需的 HTTPS 条件。

## 真实 iPhone 验证前的限制

1. 页面需放在一个 HTTPS 静态地址上，才可在 Safari 添加到主屏幕并使用 Service Worker。
2. 需要在用户手机上确认 iOS 快捷指令能否把所选付款通知的标题与正文传给「打开 URL」动作。
3. 本原型没有扫描全部通知、读取历史交易或连接支付平台；未收到/未显示的通知不会入账。
4. 当前解析为启发式规则。每次入账都应核对金额、商户、类型；退款关联也需要检查。
5. 页面通过浏览器 IndexedDB 保存数据。清除 Safari 网站数据、切换浏览器或设备不会自动同步账本；请先导出备份。

## 隐私与后续发布预留

记账模型和交易捕获入口分开。快捷指令只是一个捕获来源，未来可以增加原生 iOS App、官方消息入口或其他平台输入方式，而无需改变退款与统计规则。当前没有复制其他记账 App 的代码或品牌，也没有引入第三方库。

此原型尚未部署到公网，尚未在真实 iPhone 上验证 Shortcut 自动化。公网 HTTPS 托管、域名和未来发布所需的隐私与平台审核工作，需在选择方案后另行处理。
